# Favicon de Vainilla — plan de implementación

> **Para agentes:** SUB-SKILL REQUERIDA: usar `superpowers:subagent-driven-development`
> (recomendado) o `superpowers:executing-plans` para ejecutar tarea por tarea.
> Los pasos usan casillas (`- [ ]`) para seguimiento.

**Objetivo:** Añadir el favicon de Vainilla (V subrayada sobre círculo negro) y
eliminar el 404 de `/favicon.ico` que hoy sufre todo visitante.

**Arquitectura:** Dos fuentes SVG escritas a mano con geometría ya calculada — una
fiel al logo para tamaños grandes y otra engrosada para 16/32 px. De ellas se
generan tres archivos servidos con `rsvg-convert` e ImageMagick. No hay build: los
tres archivos se commitean.

**Stack:** SVG a mano, `rsvg-convert` (librsvg), `convert` (ImageMagick). Ambos ya
instalados. Sin dependencias nuevas en el repo.

## Restricciones globales

- Sitio estático sin build. No añadir dependencias ni orígenes externos.
- Clientes en Venezuela con conexiones lentas y dispositivos viejos: el peso total
  de los tres iconos no debe pasar de ~4 KB.
- Círculo `#1E1E1E`, trazo `#FFFFFF`. **No** son los tokens del sitio; es fidelidad
  deliberada al logo de Instagram (ver spec).
- Nada de `style=` en línea en `index.html`.
- Commits en imperativo y minúsculas. Rama `favicon`, PR a `main` con `gh`.
- Spec de referencia: `docs/superpowers/specs/2026-08-03-favicon-design.md`.

- [ ] **Paso 4: Generar el PNG de Apple y el ICO**

**Corregido durante la ejecución:** el plan original usaba ImageMagick. En esta
máquina `convert` aborta con `bad CPU type` (binario de otra arquitectura) e
`identify` no existe. Se usa Pillow, que ya es dependencia del proyecto para las
fotos y sabe escribir ICO multi-tamaño con `append_images`.

También se aplana el PNG de Apple sobre `#1E1E1E` opaco: `rsvg-convert` deja las
esquinas transparentes e iOS aplica su propia máscara de cuadrado redondeado. Como
el círculo es de ese mismo color, el resultado en píxeles es idéntico pero
predecible en cualquier versión de iOS.

```sh
TMP=$(mktemp -d)
rsvg-convert -w 16  -h 16  assets/favicon-16-32.svg -o "$TMP/f16.png"
rsvg-convert -w 32  -h 32  assets/favicon-16-32.svg -o "$TMP/f32.png"
rsvg-convert -w 180 -h 180 favicon.svg              -o "$TMP/a180.png"
python3 - "$TMP" <<'PY'
import sys, os
from PIL import Image
tmp = sys.argv[1]
i16 = Image.open(os.path.join(tmp, "f16.png")).convert("RGBA")
i32 = Image.open(os.path.join(tmp, "f32.png")).convert("RGBA")
i32.save("favicon.ico", format="ICO", append_images=[i16], sizes=[(32,32),(16,16)])
a = Image.open(os.path.join(tmp, "a180.png")).convert("RGBA")
fondo = Image.new("RGB", a.size, "#1E1E1E")
fondo.paste(a, mask=a.split()[3])
fondo.quantize(colors=16, method=Image.FASTOCTREE).save("apple-touch-icon.png", optimize=True)
PY
rm -rf "$TMP"
```

### Tarea 2: Declarar los iconos en el HTML

**Archivos:**
- Modificar: `index.html` (dentro de `<head>`, junto a los `<link rel="preload">` de las líneas 26-27)

**Interfaces:**
- Consume: `favicon.ico`, `favicon.svg`, `apple-touch-icon.png` de la tarea 1.

- [ ] **Paso 1: Comprobar que hoy hay exactamente un error de consola**

Levantar el sitio y cargarlo con un perfil de Chrome limpio:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 &
curl -s -o /dev/null -w "favicon.ico -> %{http_code}\n" http://127.0.0.1:8765/favicon.ico
```

Esperado antes del cambio: `favicon.ico -> 404`. Tras la tarea 1 ya debería dar
`200`, porque el archivo existe aunque el HTML no lo declare — el navegador lo pide
solo. La declaración explícita de esta tarea es para que los navegadores modernos
elijan el SVG y iOS encuentre el icono de pantalla de inicio.

- [ ] **Paso 2: Insertar las tres líneas**

En `index.html`, inmediatamente **después** de la línea 27
(`<link rel="preload" href="assets/fonts/josefin-sans-700.woff2" ...>`), añadir:

```html
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/favicon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
```

No añadir `<link rel="manifest">` — no hay manifiesto y está fuera de alcance.

- [ ] **Paso 3: Verificar que el HTML declara los tres y que responden**

```sh
grep -c 'rel="icon"\|rel="apple-touch-icon"' index.html
for f in /favicon.ico /favicon.svg /apple-touch-icon.png; do
  curl -s -o /dev/null -w "$f -> %{http_code}\n" "http://127.0.0.1:8765$f"
done
```

Esperado: `3`, y `200` en los tres.

- [ ] **Paso 4: Verificar cero errores de consola con Chrome real**

Esta es la prueba que cierra el problema original. Reutiliza el patrón CDP del
trabajo del service worker: lanzar Chrome headless con `--remote-debugging-port`,
habilitar `Log`, navegar y contar entradas de nivel `error`.

```sh
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
PROFILE=$(mktemp -d)
"$CHROME" --headless=new --disable-gpu --no-first-run \
  --user-data-dir="$PROFILE" --remote-debugging-port=9222 about:blank &
sleep 3
```

Y con un cliente CDP (ver `sw-test.js` del trabajo anterior como referencia del
patrón `connect`/`evaluate`): habilitar `Log.enable`, navegar a
`http://127.0.0.1:8765/`, esperar 4 s y recoger los `Log.entryAdded` de nivel
`error`.

Esperado: **0 errores**. Antes de este trabajo salía exactamente 1, el 404 del favicon.

No usar `chrome --dump-dom` para esto: sale antes de que terminen las peticiones
diferidas y da falsos negativos.

### Tarea 3: Reglas de caché para los iconos

**Archivos:**
- Modificar: `_headers`

**Interfaces:**
- Consume: las rutas de los iconos de la tarea 1.

- [ ] **Paso 1: Confirmar que hoy no encajan en ninguna regla**

```sh
grep -n '^/' _headers
```

Esperado: solo `/`, `/index.html`, `/sw.js`, `/assets/fonts/*`, `/assets/*`.
Ninguna cubre `/favicon.ico` — la regla `/` coincide con la raíz exacta, no con
rutas hijas. Sin esta tarea los iconos se sirven con el valor por defecto de
Cloudflare.

- [ ] **Paso 2: Añadir las tres reglas**

Al final de `_headers`, añadir:

```
# Los iconos van en la raíz y no encajan en ninguna regla de arriba: la regla `/`
# solo cubre la raíz exacta. Rutas literales para no solaparse con nada.
/favicon.ico
  Cache-Control: public, max-age=2592000

/favicon.svg
  Cache-Control: public, max-age=2592000

/apple-touch-icon.png
  Cache-Control: public, max-age=2592000
```

- [ ] **Paso 3: Verificar que no hay solapes nuevos**

```sh
grep -n '^/' _headers
```

Esperado: las tres rutas nuevas son literales y ninguna contiene `*`, así que no
pueden solaparse con `/assets/*` ni entre sí. El único solape del archivo sigue
siendo `/assets/fonts/*` dentro de `/assets/*`, que ya estaba documentado y degrada
sin romper nada.

Recordatorio: `_headers` no hace nada hasta migrar a Cloudflare (issue #10). En
GitHub Pages ni siquiera se sirve, porque Jekyll excluye lo que empieza por `_`.

## Autorrevisión del plan

- **Cobertura del spec:** geometría (T1 p2-3), colores (T1, en el SVG), tres archivos
  (T1 p4), marcado (T2 p2), `_headers` (T3), decisión de no tocar el service worker
  (sin tarea, es deliberadamente no-acción — recogida en el spec), receta reproducible
  (T1 p7), los cuatro pasos de verificación del spec (T1 p5-6, T2 p3-4).
- **Marcadores pendientes:** ninguno; todos los pasos llevan contenido literal.
- **Consistencia:** las rutas `favicon.svg`, `favicon.ico`, `apple-touch-icon.png` y
  `assets/favicon-16-32.svg` se usan idénticas en las cuatro tareas.
